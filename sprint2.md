# Требования и функциональность
- Проект использует C#, .NET 8 и выше, ASP.NET Core Web API.
- Код приложения хранится в том же публичном GitHub-репозитории.
- Проект собирается и запускается стандартными средствами (dotnet build, dotnet run).
- Тесты запускаются командой dotnet test и успешно проходят.
- Swagger доступен и корректно отображает новые параметры фильтрации.
- Глобальная обработка ошибок возвращает единообразные JSON-ответы для всех типов исключений.
- Фильтрация событий реализована с использованием LINQ.
- Пагинация реализована с использованием LINQ.
- Юнит-тесты покрывают основную бизнес-логику сервиса EventService.
- Тесты используют фреймворк xUnit.

# Как работать над заданием

## Этап 1. Подготовка к работе
- Убедитесь, что проектная работа первого спринта успешно завершена и принята.
- Переключитесь на ветку main вашего репозитория и выполните git pull для синхронизации.
- Создайте новую ветку sprint-2 из ветки main и переключитесь на неё.
- Все работы по этой проектной работе ведите в ветке sprint-2.

## Этап 2. Реализация глобальной обработки ошибок
1. Создайте middleware для глобальной обработки исключений:
- middleware перехватывает все необработанные исключения;
- возвращается единообразный JSON-ответ с информацией об ошибке;
- формат ответа содержит: код статуса, сообщение об ошибке;
- рекомендуем использовать Problem Details (RFC 7807) или собственный формат.
2. Зарегистрируйте middleware в pipeline приложения.
3. Обеспечьте корректные HTTP-статусы для разных типов ошибок:
- 400 Bad Request для ошибок валидации;
- 404 Not Found для ситуаций, когда ресурс не найден;
- 500 Internal Server Error для непредвиденных ошибок.
4. Опционально: добавьте логирование ошибок (используйте встроенный ILogger).

## Этап 3. Добавление фильтрации событий
1. Расширьте метод GET /events параметрами фильтрации:
- title (string, опциональный) — поиск по названию (регистронезависимый, частичное совпадение);
- from(DateTime, опциональный) — события, которые начинаются не раньше указанной даты;
- to(DateTime, опциональный) — события, которые заканчиваются не позже указанной даты.
2. Реализуйте фильтрацию с использованием LINQ в сервисе EventService:
- применять фильтры только если параметры переданы;
- все фильтры должны работать совместно (логическое И).
3. Убедитесь, что Swagger корректно отображает новые query-параметры.
4. Проверьте работу фильтрации через Swagger или другой HTTP-клиент.

## Этап 4. Добавление пагинации событий
1. Расширьте метод GET /events параметрами фильтрации:
- page (int, опциональный, c значением по умолчанию 1) — страница, которую необходимо вернуть;
- pageSize (int, опциональный, со значением по умолчанию 10) — количество элементов на странице.
2. Добавьте DTO PaginatedResult для возврата результата пагинации (общее количество событий, массив самих событий, номер текущей страницы, количество элементов на текущей странице).
3. Реализуйте пагинацию с использованием LINQ в сервисе EventService:
- получить нужные записи с использованием методов Skip и Take;
- вернуть данные в PaginatedResult.
4. Убедитесь, что Swagger корректно отображает новые query-параметры.
5. Проверьте работу пагинации через Swagger или другой HTTP-клиент.

## Этап 5. Написание юнит-тестов
1. Создайте отдельный тестовый проект (например, EventService.Tests): используйте xUnit, добавьте ссылку на основной проект.
2. Напишите тесты для сервиса EventService, покрывающие:
Успешные сценарии:
- создание события;
- получение всех событий;
- получение события по ID;
- обновление существующего события;
- удаление существующего события;
- фильтрация по названию;
- фильтрация по датам (startDate, endDate);
- пагинация событий;
- комбинированная фильтрация.
Неуспешные сценарии:
- попытка получить событие с несуществующим ID;
- попытка обновить событие с несуществующим ID;
- создание события с некорректными данными (если валидация в сервисе);
- обновление события с некорректными датами (EndAt раньше StartAt).
3. Убедитесь, что все тесты проходят успешно (dotnet test).

## Этап 6. Проверка и оформление
1. Протестируйте работу API через Swagger:
- проверьте фильтрацию событий с различными комбинациями параметров;
- убедитесь, что ошибки возвращаются в едином формате.
2. Обновите README.md:
- добавьте описание новых параметров фильтрации для GET /events;
- добавьте инструкции по запуску тестов (dotnet test);
- укажите формат ответа при ошибках.
3. Убедитесь, что:
- проект собирается и запускается без ошибок;
- все тесты проходят успешно.
4. Сделайте финальный commit и push всех изменений в ветку sprint-2 на GitHub.

## Этап 7. Сдача работы
- Создайте pull request из ветки sprint-2 в ветку main вашего репозитория.
- Скопируйте ссылку на созданный pull request.
- В тренажёре в уроке с проектом вставьте ссылку на pull request в поле для ссылки и нажмите «Отправить».
- Ревьюер проверит вашу работу по чек-листу. Он оставит комментарии в pull request, если потребуются правки.
- После того, как правки по всем комментариям будут внесены, ревьюер одобрит pull request.
- Выполните слияние изменений в ветку main.
